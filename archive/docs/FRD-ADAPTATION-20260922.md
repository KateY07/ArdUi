# 新版 FRD 适配进度 · 2026-09-22

> 本文保留正式交付前的阶段记录。随后已收到用户指定的 FRD v1.pre13，完成正式黑盒联调、离线升级验证及 ArdUi v2.pre11 本机发布；最终结果见 [正式联调及交付记录](FRD-PRE13-VALIDATION-20260922.md)。下文“仍遗留”描述的是当时状态。

本轮只修改 ArdUi。FRD 开发组负责 FRD 源码和协议实现；本侧依据用户转来的 CLI/端口约定及正式交付二进制进行黑盒适配。其他 ARD/Iroh/ArdUi 审计问题先搁置。本记录不表示已发布或部署。

## 上一轮已经完成的 4 类修正

| 项目 | 已完成内容 | 验证边界 |
|---|---|---|
| 透明传输 | 删除原 FRD 业务握手解析、业务端口改写、magic/业务长度识别 | 任意 TCP 字节流、任意允许大小的 UDP 数据报测试通过 |
| 单端口映射 | 被控端授权 `--port P` 的 TCP/UDP，主控映射至同一入口 `Q`，P 与 Q 可以不同 | 不要求额外视频、诊断或输入端口 |
| 多 TCP 与半关闭 | 同入口为每条 TCP 建立独立上游流，保留半关闭后的反向传输 | 上轮覆盖 2 路并发，本轮补齐 8 路持续并发 |
| UDP 回程与清理 | 按本地来源维护回程映射，保持内容和数据报边界，处理单流发送失败与退出清理 | 上轮为隔离转发测试，不能等同于新版 FRD 完整联调 |

## 本轮完成

1. **消除日志文案依赖**：不再解析 `Remote listener ready:` 决定启动成功。通过 Windows 公开接口查询启动进程拥有的 `127.0.0.1:port` TCP/UDP 监听；不发送 FRD 业务包，不读取 FRD 内部配置。stdout/stderr 持续收集用于诊断。
2. **启动期间取消与错误可见**：等待监听关联请求及授权会话的取消；启动退出报告实际退出码；TCP/UDP 未同时监听时限时失败，其他进程占用同端口不能冒充就绪。
3. **明确多连接容量并补充回归**：保留 8 条并发 TCP 的资源上限，超限只拒绝新连接并记录原因；测试同入口 8 路独立数据、单路半关闭/关闭/重建对其他连接的影响。
4. **黑盒联调输入和失败定位**：联调脚本必须显式指定开发组交付的 FRD 二进制，记录路径及 SHA-256，隔离测试数据目录；撤销测试分开报告被控清理和主控未结束，不放宽原验收条件。

生产改动位于 `Frd/FrdListener.cs`、`Frd/FrdRuntime.cs`、`Frd/FrdForwarder.cs`。没有修改 ARD/Iroh 或 FRD 源码，没有修改用户配置、密钥、已安装程序或发布包。
