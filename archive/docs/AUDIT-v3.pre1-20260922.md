### 职责与改动边界

- **FRD 集成边界已纠正**：`FrdForwarder` 按一个目标端口双向转发 TCP 字节流和 UDP 数据报；多 TCP 连接独立；`FrdListener` 查询 PID 所属 TCP/UDP 监听；日志仅用于诊断。没有发现现行运行路径解析视频、输入、剪贴板等 FRD 私有协议。FRD 内部复用、鉴权、业务恢复仍归 FRD。
- **Overlay 自有协议属于 ArdUi**：信用帧、内层加密、候选 C 路由和恢复并非 FRD 协议解析，也不是替换 Iroh 的打洞算法。不过本次协议升为 3，双方必须同时升级；不能声称与 v2 无缝兼容。
- **ARD 进程恢复边界改善**：Engine 不再因十秒路径不可用杀死正常 ARD，只在进程退出时重启。整个 Overlay 无路径超时仍会触发会话重建；这是 ArdUi 的生命周期策略，不能报告为 Iroh 已判定连接不可恢复。
- **ARD 路径诊断仍是部分完成**：消费端过滤了 selected/closed/lagged，但仍依赖文本、没有结构化快照协商。收到丢事件通知后显示未知是保守处理，不等于已经完成重同步。跨组件 07 不能标为全部完成。
- **根 ARD 已跟踪源码本轮没有修改**：只读检查根仓库 status 未见已跟踪文件改动。ArdUi 的 README、Core/Release.cs、release-public.pem 没有 diff。未改变用户暂缓 05 的决定。
- **历史文档删除需单独核实来源**：工作区存在 V2 历史验证文档和增强中继畅想文档的删除状态，不能证明是本轮删除。不可把全部工作区直接打包成源码提交；恢复提交前应确认这些删除的授权和归档位置。
