# ArdUi v3.pre17

- Bundle ARD v4.pre2 (4.0.0-pre.2), including its tracked Iroh, Noq, netwatch and
  portmapper patches. Retain FRD v2.pre3.
- Preserve ARD startup milestones independently of bounded diagnostic history.
  Dense logs previously evicted READY before observation, causing a false
  timeout despite an established connection.
- Generate a OneSetup EXE and an offline ZIP from the same payload. Record the
  actual ARD version and SHA-256 in components.json as packaging metadata only.
- Keep existing data and identity keys unchanged. Install application files into
  versions/v3.pre17 and refresh the launcher/startup shortcut. Users must
  preinstall .NET 8 and .NET 10 runtimes.

Validation: headless UI tests; a real child emitting 500 diagnostic lines after
READY; real ARD enrollment, reconnect, revoke and three add/remove cycles.
Candidate integration initially timed out during activation after base TCP/UDP
passed. An isolated repeat passed both direct relay legs, same-socket TCP/UDP
switching, fallback after killing C and revocation. Killing the base ARD process
recovered the original business socket and local port in 33.7 seconds. The first
activation timeout's root cause remains unconfirmed and its evidence is retained.

The v3.pre16 candidate failed integration before the READY fix and is superseded.
Previously generated release files are not overwritten.
