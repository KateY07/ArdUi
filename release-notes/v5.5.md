# ArdUi v5.5

**不兼容旧版本：** v5.5 只能与 v5.5 及以上的 ArdUi 互连，官方服务器也已拒绝 v5.5 以下的客户端。请所有设备一起升级。

**角色与职责**
- 网络只有三种角色：M、ArdFerry、ArdUi，每个角色只配置一个 HTTPS 域名；一个网络只有一个 M。见 README 顶部和 `ROLES.md`。
- ArdUi 的配置不变（`config.json` 里的 `server` 就是 M 的域名）。中继目录和 M 的公钥改由 M 告诉客户端；`config.json` 里旧的 `relay`、`relayKey` 两项不再使用，留着也没有影响。

**安全**
- 每个会话的密钥交换都由双方设备密钥签名：即使有人拿到会话令牌，也冒充不了已授权的设备。
- 被控端的本地入口每个会话只接受一次准入，本机其他程序拿不到会话令牌。
- 撤销授权或关闭被控时，正在等待确认的请求也会被拒绝。
- 收到的文件带“来自网络”标记，运行前 Windows 会提示；每次连接最多接收 10 GB。
- 首次连接密码按设备限制尝试次数；发给对方的错误信息不再包含本机路径、账户名和计算机名。
- 同时进行的请求过多时只回复“对端正忙”，不再断开整个会话。

**权限**
- 新增“对话”“文件”“通话”三项权限，与 FRD、RDP 一起在被控端逐设备授权，双向生效。旧授权保持原有能力。
- 移除 SMB 文件共享（原本就不可用）。

**集成 FRD v5.4**
- 新增：被控端悬浮面板里的“截屏”标注工具：抓取被控机主屏后在图片上标注，保存为 PNG 或复制到剪贴板，不影响被控机的操作，也不发给主控端。
- 包含 v5.3 的修复：被控端打开任务管理器（管理员窗口）后键鼠无法转发。需要在被控端安装一次 FRD 的被控服务：运行安装包里 `frd` 目录中的 `frd-service-*-setup.exe` 并确认 UAC，也可以在 FRD 界面点“安装被控服务”。已装 v5.3 被控服务的不必重装。
- **安全提示：** 装了被控服务之后，已连接并有输入权限的主控端可以操作被控机上的管理员窗口，与它能操作 UAC 和锁屏界面是同一级别的授权。只给信任的设备开 FRD 权限。
- FRD 协议未变。

**其他修复**
- 装了 Hyper-V、WSL、Docker 等软件的电脑上，会话或 FRD 偶尔建立不起来（Windows 保留的 UDP 端口段导致端口绑定失败），现已自动换端口重试。

**自托管**
- `selfhost.sh` 支持只用公网 IP 部署（Let's Encrypt 短期 IP 证书）、完全离线安装（`--wheels`），服务运行在加固的沙箱里。
- ArdFerry（流量转发节点）只需配置 M 的域名即可加入网络：自己生成密钥、自助登记，M 探测通过后才会被使用。安装器会自动下载并校验官方 `iroh-relay`，支持 UPnP 和 NAT-PMP 端口映射。
