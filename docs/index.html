Why ArdUi为什么选择 ArdUi

Built on ARD (Iroh). Every device has a permanent key; its public key is its identity.基于 ARD（Iroh）。每台设备有一对永久密钥，公钥就是它的身份。

High performance高性能

Direct UDP paths between devices, with automatic fallback to a relay when a direct path is not possible. Low-latency desktop streaming through FRD.设备之间优先走 UDP 直连，直连不通时自动回退到中继。通过 FRD 提供低延迟的桌面画面。

Peer-to-peer点对点

Your data goes straight from one device to the other. The directory server only hands out device IDs and coordinates the connection; it is never in the data path.数据直接在两台设备之间传输。目录服务器只分配设备编号、协调连接，不在数据路径上。

End-to-end encrypted端到端加密

Identities are verified before any password is sent, and the server never receives passwords. The host approves each controlling device, and can revoke it at any time.先核对身份，再发送密码，服务器永远收不到密码。被控端逐设备批准，随时可以撤销。

Self-hostable可自托管

Run your own directory server on a Linux machine with a single command, HTTPS included. Everything is open source.在 Linux 服务器上用一条命令部署自己的目录服务器，自带 HTTPS。全部开源。

What is in the box功能

Device ID connect编号连接

Enter the device ID and a one-time password, compare the device fingerprint, and the host approves. Later connections need no password.输入设备编号和一次性密码，核对设备指纹，由被控端同意。之后重连无需密码。

Per-device permissions逐设备授权

Allow FRD, RDP and file access separately for each device (FRD only by default), or accept a connection just once.为每台设备分别开放 FRD、RDP、文件（默认只开 FRD），也可以“仅接受这一次”。

Chat and file transfer对话与文件传输

Text, images and files up to 2 GB, with speed and progress, cancellable, and chat keeps working during a transfer.文字、图片、文件（最大 2 GB），显示速度与进度，可取消，传输时仍可聊天。

Audit recording审计录屏

While a device uses the screen, it is recorded locally on the host (10 fps, up to 10 GB, oldest overwritten) with the Windows H.264 encoder.对方使用屏幕时，在被控端本地录制（10 帧/秒，最多 10 GB，循环覆盖），使用 Windows 自带的 H.264 编码器。

Voice calls语音通话

Call a connected device over the same encrypted link: Opus, ringing, answer, mute, hang up from the window or the island. A side without a working microphone can still join, and both are told.沿用同一条加密链路呼叫已连接的设备：Opus 音频，响铃、接听、静音、挂断，窗口和灵动岛都能操作。一方没有可用麦克风也能通话，双方都会收到提示。

Microphone diagnosis麦克风诊断

Devices, Windows privacy switches, a live level test, record-and-playback and a speaker test, all on this machine.音频设备、Windows 隐私开关、实时音量测试、录音回放和扬声器测试，全部在本机完成。

Network diagnosis网络诊断

Can two devices connect directly? Your NAT type, exits, UPnP, and a verdict, confirmed with real traffic by the server: it probes the ports you open from the outside.两台设备能否直连？NAT 类型、出口、UPnP 和结论，并由服务器用真实流量确认：从外部探测你开放的端口。

Floating island灵动岛

A small draggable pill near the tray: connection state, message bubbles, unread count, file progress and calls. Click to open the chat.托盘上方可拖动的小胶囊：连接状态、消息气泡、未读数、文件进度和通话，点击打开对话。

No admin rights无需管理员权限

No drivers and no network changes. Your device identity and settings are kept across upgrades.不装驱动，不改网络设置；升级时保留设备身份和配置。

How data flows:数据怎么走： after coordination, the two devices open an end-to-end encrypted connection through ARD (direct first, relay only if needed). The server is not on the data path and cannot read it.协调完成后，两台设备经 ARD 建立端到端加密连接（直连优先，不通时才走中继）。服务器不在数据路径上，也读不了数据。

Quick start快速入门

Install the same app on both computers. Being controlled is off by default, so if you only want to control other machines you can leave it off.两台电脑装同一个应用。被控功能默认关闭，只想控制别人的话不用开。

Download and install下载并安装

Get the latest ArdUi-vX.exe from GitHub Releases and run it. It installs to %LOCALAPPDATA%\ArdUi and keeps your identity and settings on upgrades. The .NET 8 desktop runtime is required; FFmpeg is not included (optional extension, see the README).到 GitHub Releases 下载最新的 ArdUi-vX.exe 并运行。安装在 %LOCALAPPDATA%\ArdUi，升级时保留设备身份和配置。需要先装 .NET 8 桌面运行时；安装包不含 FFmpeg（可选扩展，见 README）。

On the host: allow control被控端：允许被控

On the computer you want to reach, switch on “Allow control”. You get a device ID, and a first-connection password that shows for 10 seconds when you click it. Give both to the person connecting.在要被访问的电脑上打开“允许被控”，得到设备编号；点击后显示 10 秒的首次密码。把两者告诉对方。

On the controller: connect主控端：连接

Enter the ID and password and press Connect. Compare the full device fingerprint over a separate channel, such as a phone call. The host accepts (or accepts just once) and chooses which features to allow.输入编号与密码，点“连接”。用电话等独立渠道核对完整设备指纹，被控端点“接受”（或“仅接受这一次”）并选择开放的功能。

Use it开始使用

Authorized devices appear in the list: FRD for the desktop, Desktop for RDP, Files for shares, and the chat icon for messages and files.已授权的设备出现在列表里：FRD 看桌面，“桌面”用 RDP，“文件”访问共享，对话图标发消息和文件。

Self-hosting自托管

By default ArdUi uses a public directory service. To keep everything in your hands, deploy your own directory server on a Linux machine with a domain name.默认使用公共的设备目录服务。想自己掌握，可以在有域名的 Linux 服务器上部署自己的目录服务器。

One-command install一键部署

Needs Linux with systemd, root, a domain pointing at the machine, and ports 80/443 open. It installs a Python environment, the directory service and Caddy with automatic HTTPS.需要：Linux（systemd）、root 权限、已指向本机的域名、开放 80/443 端口。脚本安装 Python 环境、目录服务和带自动 HTTPS 的 Caddy。

curl -fsSL https://raw.githubusercontent.com/KateY07/ArdUi/main/selfhost.sh | sudo bash -s -- --domain ardui.example.com

Preview first with --dry-run; behind your own proxy use --http-only; remove with --uninstall (data is kept). Read the script.先预览：--dry-run；已有反向代理：--http-only；卸载：--uninstall（数据保留）。查看脚本。

Point the clients at it让客户端使用它

The script prints this at the end. On every computer, edit the ArdUi config and restart ArdUi:脚本结束时会打印这一步。在每台电脑上改 ArdUi 配置，然后重启：

# %LOCALAPPDATA%\ArdUi\data\config.json
{
  "server": "https://ardui.example.com/"
}

Check it: open https://your-domain/api/health, it should return "ok": true.验证：打开 https://你的域名/api/health，应返回 "ok": true。
