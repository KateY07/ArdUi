# 前五项修正与验证

日期：2026-09-22。用户授权范围为按影响排序的前五项；本轮只修 ArdUi，没有访问或修改 FRD 源码，没有修改 ARD/Iroh，没有处理 Actions 或 05 更新验签。

## 修正

1. **UDP 单流故障隔离**：Overlay 目标映射创建和发送错误在该流处理并移除；Gateway 对数据报处理设置隔离边界，异常记日志后继续接收。停止网关仍按取消退出，不吞掉错误。
2. **重连映射竞争**：LocalUdpFlow 保留所属 Session，发送前检查是否仍是当前会话；创建后发布时再次核验。即使旧流在 Reset 快照之后才进入字典，后续数据报也会识别并清理，不能持续复用旧端口。
3. **TCP 流窗口**：握手增加可选 MaxFlowCredits；缺少字段的旧 v3 对端按 16 帧处理。双方支持时，初始仍为 16 帧，接收端每实际写入一帧，可从共享预算借用一个额外信用。单流最多 512 帧，即 8 MiB；额外接收信用共享上限为 2048 帧，即 32 MiB，流结束归还。在既有 128 流上限下，基础额度加额外额度的接收业务载荷上限为 64 MiB；可靠重放缓冲、帧元数据和系统 socket 缓冲另计。每帧仍限制 16 KiB。慢流不返还已消耗信用，其他流保留基础额度；没有改成无限队列。
4. **候选带宽判定**：正常基准路径下，双方可比较的有效带宽测量缺失时不自动切换；保留至少 70% 基准带宽的保护。基准样本不足不视为失败；已有至少 8 次样本且成功不足 4 次时允许救援候选，不要求未知带宽阻塞恢复。
5. **非模态指纹确认**：使用有主窗口归属的非模态窗口，不再禁用主窗口；只有明确点击同意才能批准，拒绝、关闭和取消返回拒绝。主窗口安全操作可用，未删除指纹核对。

v3 的能力协商没有改变 v2 不兼容的既定边界。FRD 仍只使用公开 CLI 和单端口透明 TCP/UDP 转发，不解析其业务协议。

### 延迟反馈对照

用测试流为返回方向的 TCP ACK/信用帧注入固定 100 ms 延迟；8 MiB 随机数据逐字节完整性由 SHA-256 比对。相同实现分别协商旧的 16 帧上限与新上限，最后一次结果：

| 模式 | 传输用时 |
|---|---:|
| 固定 16 帧 | 3.503 秒 |
| 渐进信用窗口 | 0.488 秒 |

约 7.2 倍的本测试吞吐改善；这仅证明旧窗口在延迟反馈下的瓶颈被解除，不是公网速度，不代表所有业务或网络均有同样收益。新窗口仍受明确的单流和共享内存上限约束。
