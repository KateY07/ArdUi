# FRD v1.pre13 正式联调与 ArdUi v2.pre11 本机交付

日期：2026-09-22。

本轮仅开发 ArdUi，使用用户指定的 FRD 正式二进制和公开 CLI 说明进行黑盒联调。未访问或修改 FRD 源码，未修改 ARD/Iroh，未修改锁定 README。其他审计问题按用户要求搁置。

## 已确认接口及修正

- 被控端使用 `--listen <地址> --port P`，在 P 同时监听 TCP、UDP；主控使用 `--connect <地址> --port Q`，全部连接和数据报目标均为 Q。地址参数与端口参数分开传入。
- ArdUi 对 Q 与 P 建立一组透明 TCP/UDP 映射，允许端口号不同；每条 TCP 连接保持独立字节流和生命周期。
- 转发入口保留 8 条并发 TCP 的上限，满足对方声明的单会话最多 4 条；支持最大 1482 字节 UDP 数据报，满足对方声明的最大 1172 字节。
- UDP 按实际来源端点维护双向回程映射，保留数据报内容及边界。FRD 自行处理会话证明、鉴权和协议分流。
- 已删除 ArdUi 对 FRD 握手、内部业务端口和消息类型的解析或改写；不要求动态端口或 `P+1`。
- 启动就绪依据启动进程实际拥有的 TCP/UDP 监听判定，不依赖 FRD 日志文案，不发送探测业务包。日志仍完整收集用于诊断。
- FRD 运行路径由安装器维护的指针决定，保留外部自定义路径能力；运行时不硬编码 FRD 版本，也不以内部文件布局判断完整性。安装器仍验证分发文件哈希。

此前阶段记录见 [FRD-ADAPTATION-20260922.md](FRD-ADAPTATION-20260922.md)。

### 撤销测试预期的澄清

此前预览测试将“远端撤销后主控进程必须自动退出”作为通过条件，因此记录过超时。正式交付包的公开说明明确：连接关闭后，主控窗口保留关闭原因及重连入口。依据这项已交付的生命周期说明，本轮分开验证：

1. 远端撤销必须移除授权会话并停止被控 FRD。
2. 在 ArdUi 主控主动断开时，必须清理本地主控 FRD 和转发入口。

以上两项均通过。不能据此宣称远端撤销会自动关闭主控窗口；历史超时记录仍保留。

## 验证边界及遗留

- 本轮没有注入真实键鼠输入或同步剪贴板；键鼠、剪贴板、鼠标形状及真实双机操作体验仍需人工验收。画面呈现及透明数据测试不替代这些验收。
- 正式联调使用隔离身份和本机测试进程，并未验证此次版本在真实 LAN/公网环境下的路径迁移体验。
- Overlay 慢流阻塞、通用连接恢复监视器等其他审计问题仍按原报告跟踪，本轮没有解决或重新验收。
- 安装回归使用隔离目录并跳过系统启动项及实际 GUI 启动，用户真实配置和密钥未被写入。常规安装保留原有启动项创建逻辑，本轮没有更改该逻辑。
