# ArdUi v4.pre1

WITHDRAWN LOCAL BUILD — do not install. No GitHub release was uploaded.
The GUI executable attempted to set console encoding without a valid console
handle, and the packaging script did not reliably wait for its failing self-test.
Use v4.pre2, which removes that initialization and waits for process exit.

Primary device sessions use unmodified official EasyTier binaries in no-TUN mode.
No adapter installation, elevation or FRD protocol changes are required.

Device Ed25519 identity files, machine codes, saved grants and user configuration
remain in the existing data directory. Signed connection requests and offers carry
temporary X25519 public keys, the transport identifier and gateway port. Both sides
derive an isolated network secret using X25519/HKDF; the directory and relay never
receive that secret. Secure mode and a pinned bootstrap public key are required.
Only the private application gateway port is allowed by EasyTier. RDP, SMB and FRD
remain behind ArdUi authorization. Existing inner encryption and stream recovery
remain in place. Both endpoints must use v4; incompatible offers are rejected.

EasyTier state comes from its structured local CLI. Original stderr and state
changes remain available in diagnostics. Process restart reuses the same temporary
configuration and local forwarding port.

The existing optional ArdTransit candidate implementation is retained with its ARD
dependency for compatibility; it is separate from the new EasyTier base transport.
It has not been silently removed or reimplemented. Installer payload includes the
official runtime DLLs and a relay.json alongside the executable, never in user data.

Validation: build (zero warnings/errors), headless UI/identity self-tests, eight
concurrent TCP streams with half-close, UDP 1172/1200-byte return mappings,
authenticated overlay full-sized UDP, a 10 MiB stream, candidate switch/fallback,
replay/tamper rejection, first consent, revocation, three add/remove cycles and
child-process recovery passed in isolated data directories. An NJ-bootstrap smoke
test passed and reported P2P; this is not a claim of all-network migration coverage.

The raw 1500-byte UDP probe failed in this official no-TUN configuration. ArdUi's
existing application overlay fragments larger datagrams; its full-sized UDP test
passed. The raw limitation is retained here rather than reported as a pass.
