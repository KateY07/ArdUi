# 转交 ARD 团队：依赖安全、路径诊断及 QAD 配置

核对基线：ARD v3.pre1。以下三项由 ARD/ArdRelay 团队负责；消费端会继续修复自身会话与转发逻辑，不要求修改应用业务协议。

## A. rustls 依赖升级（原问题 06）

`Cargo.lock` 中 rustls 为 0.23.43。官方公告 GHSA-2mjx-qc3c-rqvc 影响 0.23.13–0.23.44，修复版 0.23.45。问题是 TLS 1.3 跨加密阶段握手消息的边界验证，不能夸大为可伪造对端或解密业务。

请升级兼容的上游修复版本及锁文件，重新构建 ARD 与 ArdRelay，不在本地修改 rustls/Iroh 密码学源码。请回归正确公钥连接、错误公钥/证书拒绝、候选发布查询、TCP/UDP 透明转发，并交付版本号及二进制 SHA-256。

依据：https://github.com/rustls/rustls/security/advisories/GHSA-2mjx-qc3c-rqvc

## B. 明确的路径状态和受控打洞诊断（原问题 07 的 ARD 部分）

现有 `src/main.rs` 输出 Selected、Closed、Lagged 等人类可读日志。Closed 同样带 transport/network 字段；消费端若按字段更新会误判当前路径。Lagged 后缺少完整当前状态，默认 info 日志不足以定位候选发现、探测与路径选择的阶段。

请提供可选、版本化的机器可读事件或状态快照，保留原有日志。建议至少包含 schemaVersion、事件类型、连接/隧道标识、递增序号、单调时间、当前路径 ID、transport、network、RTT 和原因。区分路径候选、新路径可用、当前选择、非当前路径关闭、当前路径关闭、连接关闭；启动、订阅或 Lagged 后提供完整快照，无当前路径时明确表示 unknown/recovering。

同时保留显式详细诊断开关，能够辨别候选未获得、探测已发、无回复、路径验证成功但未选中。地址等敏感字段必须可受控并由消费端脱敏；不得输出私钥、能力令牌或业务数据。

验收：关闭非当前路径不改变当前状态；当前路径关闭不仍被报告为直连；事件丢失可通过快照重同步。消费端负责解析与展示，不要求 Iroh 更改原生路径选择算法。

## C. QAD 自定义端口贯通（原问题 11）

服务端 `relay/src/main.rs` 接受 `--qad-listen IP:PORT`，TCP 候选服务同样绑定此端口；客户端 `src/main.rs` 公钥预校验固定 7842，`src/address_lookup.rs` 使用固定 `ard_discovery::PORT`，Iroh 的 relay QAD 配置未贯通该值。

复现：将隔离 ArdRelay 的 QAD 端口设置为非 7842，使用正确 relay URL 与固定公钥连接；客户端仍访问 7842，初始化/候选发现失败。默认部署不受此项影响。

请为客户端提供明确的 QAD/发现端口配置，并将同一配置贯穿公钥预核验、TCP 候选发现、Iroh Relay/QAD。默认保持 7842；HTTP relay 端口与 QAD 端口不可混淆。请给出最终 CLI 名称、能力探测方式与兼容说明，消费端再透传；消费端不会向现有二进制发送它不支持的参数。

验收：默认和非默认端口均完成握手、候选交换与可达网络下的直连；错误端口明确报错；保持现有 NJ 8080/8090 配置，不将端口配置问题当成打洞算法问题。
