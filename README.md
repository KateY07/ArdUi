# ArdUi.exe

ArdUi 是一个面向 Windows 的轻量桌面应用，基于 ARD 建立主控端与被控端之间的认证连接。仅主控端使用 Wintun，为被控端提供直观、固定的虚拟 IP 访问入口；被控端无需安装 Wintun。用户可以输入或扫描被控端的 EndpointId，连接后通过固定地址访问远程桌面和文件共享。

## 产品定位

让主控端以接近局域网的方式访问一台或多台 Windows 被控设备。ArdUi 负责展示设备身份、发起和管理连接、配置虚拟网络，并提供清晰的连接状态和访问入口。

远程桌面使用 Windows 远程桌面客户端，文件共享使用 Windows 文件资源管理器。ArdUi 不内置远程桌面画面，也不实现独立的文件传输协议。

## 主控端与被控端

- **主控端**：发起连接，使用 Wintun 提供虚拟 IP 入口，将访问该地址的流量通过 ARD 转发到被控端。
- **被控端**：接受授权连接，将 ARD 转发的流量交给本机远程桌面、文件共享等服务，无需安装 Wintun，也无需配置虚拟网卡或虚拟 IP。

两端使用同一个 ArdUi 应用，仅作为被控端运行时不加载 Wintun、不创建虚拟网卡。

## 固定访问地址

主控端可以同时连接多台被控端，并为每个不同的 EndpointId 分配一个独立、固定的虚拟 IP。地址保持 `10.x.x.1` 形式，通过不同网段区分设备。本文暂以以下地址作为示例，具体地址池在开发前确定：

| 被控设备 | 固定虚拟 IP | 远程桌面 | 文件共享 |
| --- | --- | --- | --- |
| 设备 A | `10.77.0.1` | `10.77.0.1:3389` | `\\10.77.0.1` |
| 设备 B | `10.77.1.1` | `10.77.1.1:3389` | `\\10.77.1.1` |
| 设备 C | `10.77.2.1` | `10.77.2.1:3389` | `\\10.77.2.1` |

EndpointId 与虚拟 IP 的对应关系由主控端自动分配并持久保存。同一设备的地址不随连接顺序、断线、重启或对端真实网络地址变化而重新分配，用户无需反复配置 IP。已保存的地址不会因设备暂时离线而分配给其他设备。

这些地址是主控端为各被控端提供的本地虚拟访问入口，并非配置在被控端网卡上的实际 IP。连接时通过 EndpointId 确定设备，虚拟 IP 负责提供稳定的业务访问地址。多台设备的连接、流量映射和状态相互独立，断开其中一台不影响其他连接。

## 技术与交付约束

- 使用 Avalonia 开发桌面界面，目标程序名为 `ArdUi.exe`。
- 依赖 .NET 8，使用 C# 代码构建界面和交互，不使用 XAML。
- 界面简约，以设备身份、连接操作、连接状态和访问入口为核心。
- 以 ZIP 压缩包交付，在已具备所需 .NET 8 运行环境的 Windows 电脑上解压即用，无须安装 ArdUi。
- 压缩包包含应用所需文件、ARD 程序、供主控端使用的 Wintun 运行组件，以及预置 Relay 信息的配置文件。具体打包布局在开发阶段确定。

两端均需具备 .NET 8 运行环境；虚拟网卡操作所需的系统权限仅涉及主控端。

## 首次打开

应用启动后自动读取配置，并创建或读取本机 ARD 身份。主界面直接展示：

- 本机 EndpointId，支持复制。
- 对应二维码，便于另一台设备扫描。
- 远程 EndpointId 输入框，以及扫描入口。
- 连接按钮和当前连接状态。

二维码用于交换公开的 EndpointId，不包含身份私钥。身份应持久保存，正常关闭和重新打开应用后保持不变。ArdUi 应固定 ARD 的身份工作目录，避免启动方式变化导致设备身份变化。

## 连接流程

1. 双方打开 ArdUi，获得各自的 EndpointId。
2. 主控端用户输入或扫描被控端的 EndpointId，选定要连接的设备。
3. 应用通过配置中的 Relay 建立 ARD 连接，并完成对端身份核验及双方授权。
4. 主控端读取该 EndpointId 已保存的虚拟 IP；首次连接时自动分配一个未占用的地址。随后启用对应的 Wintun 虚拟访问入口，被控端仅接收 ARD 转发的业务流量。
5. 用户通过该设备的固定虚拟 IP 使用远程桌面或文件共享，例如 `10.77.0.1:3389` 和 `\\10.77.0.1`。
6. 用户可继续添加其他被控端，应用为其分配不同的虚拟 IP，并同时保持已有连接。

输入或扫描 EndpointId 仅表示选定目标，不等同于对端已经授权访问。双方授权的具体交互形式将在后续设计中确定。

## 连接后的界面

主控端以简约设备列表展示每台被控端的 EndpointId、固定访问地址和独立连接状态，并为每台设备提供以下操作：

- **远程桌面**：启动 Windows 远程桌面客户端，连接所选设备的虚拟 IP 和 `3389` 端口。
- **文件共享**：在 Windows 文件资源管理器中打开 `\\所选设备虚拟IP`。
- **复制地址**：复制被控端的固定访问地址，供其他应用使用。
- **断开连接**：仅结束所选设备的连接，清理该会话的流量映射和网络资源，保留固定地址设置供下次使用，不影响其他设备。

被控端展示本机 EndpointId、二维码、授权及连接状态，无需展示或配置本机虚拟 IP。

远程桌面和文件共享需由对端预先开启，并使用其原有的 Windows 账户、访问权限和认证方式。ArdUi 提供网络可达性，不代替业务服务的授权。

## 状态反馈

界面应针对每台设备清楚区分未连接、正在连接、已连接、连接已断开和连接失败。发生错误时，用简短文字说明原因，并提供适当的重试入口。

## 配置文件

应用随包提供配置文件，用户无需在每次连接时填写 Relay。以下为拟定的最小配置示例：

```json
{
  "relay": "http://175.27.160.144:8080"
}
```

`8080` 是 ARD Relay 端口；`8090` 是下载服务端口，不用于建立 ARD 连接。身份私钥不存放在此配置文件中。

## 职责边界与待定事项

- **ARD**：核验对端身份，提供认证后的 TCP/UDP 载荷转发。
- **ArdUi 主控端**：管理界面、ARD 进程和连接状态，负责 Wintun 虚拟网卡、固定虚拟 IP、路由、虚拟 IP 流量与 TCP/UDP 转发之间的适配及会话清理。
- **ArdUi 被控端**：管理界面、身份授权及 ARD 进程，将获准的业务流量转发至本机服务，不处理 Wintun 虚拟网卡。
- **Windows 业务服务**：提供远程桌面、文件共享及其账户认证。

现有 ARD 本身是端口转发工具。主控端需要把发往固定虚拟 IP 的流量适配为 ARD 可转发的 TCP/UDP 流，被控端再交给本机服务。产品形态采用主控端虚拟 IP 到被控端本地服务的映射，不要求被控端接收原始 IP 包或安装虚拟网卡。具体适配实现留待开发阶段确定。
