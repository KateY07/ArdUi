# ArdUi.exe

ArdUi 是基于 ARD 的 Windows 远程访问应用，使用 Avalonia 和 .NET 8，以简约的“已授权设备”列表为主界面。用户通过 6 位机器编号添加设备，经密码验证、双方身份核对和被控端同意后，即可从列表打开远程桌面或 SMB 文件共享。

## 产品组成

| 组成 | 职责 |
| --- | --- |
| install.ps1 | 唯一面向用户的交付入口，负责完整安装过程，包括下载客户端、创建或恢复永久私钥、TPM 持久化、配置、升级和启动。 |
| ArdUi.exe | 展示本机身份、维护已授权设备、申请和批准访问、打开远程桌面或文件共享。 |
| arduiserver | 位于 `https://f.visnova.cn/`，分配机器编号，提供设备查询、在线状态和连接协调。 |
| ARD | 验证通信对端，承载端到端加密连接和业务流量。 |

最终只向用户提供 `irm https://f.visnova.cn/ardui/install.ps1 | iex` 这一条安装命令。脚本自动下载自包含的 Windows x64 客户端 `ArdUi.exe`，其中包含 .NET 8 运行环境和必要依赖；用户无需单独下载 EXE、运行安装模式或准备 ARD 文件。客户端运行产物仍为一个自包含 EXE，不另交付安装器 EXE。

两端使用同一应用。被控功能默认关闭，用户可以只使用主控功能；关闭被控功能不影响访问已经获得授权的远程设备。开启“允许远程访问”的设备就是被控设备，界面统一称为“设备”，避免与中央协调服务 arduiserver 混淆。

双方均不需要 Wintun、tun2socks、虚拟网卡、虚拟 IP 或路由配置。用户不用填写 IP、端口或 Relay，日常运行不请求管理员权限。

## 安装、身份与机器编号

`install.ps1` 负责创建、持久化与恢复身份，客户端普通运行模式不负责生成身份：

1. 安装时查找 TPM 中的 ArdUi 身份记录；存在则恢复原私钥，不存在才首次生成 Ed25519 私钥并持久保存。
2. 恢复所需的封装数据与必要元数据也必须跨重装保留，不能仅依赖系统盘或旧 Windows 用户配置。
3. 安装器准备 ARD 使用的本地密钥文件，并设置访问权限。
4. 日常启动只读取本地文件，不读取 TPM、不自动重新生成密钥。文件缺失时提示运行安装器修复。
5. 已有记录但恢复失败时停止并提示，不能以生成新身份掩盖错误。
6. 在同一设备、TPM 保持原状态的约定下，重装后恢复相同私钥与 EndpointId。更新程序不覆盖身份。

TPM 持久对象、NV 存储及 Windows 访问权限需要先完成实机验证；不能把普通的 Windows CNG 密钥保存直接视为已经实现跨重装恢复。此设计让 TPM 承担恢复来源，运行期间本地私钥文件仍需保护。

客户端通过 HTTPS 注册，并签名证明持有设备私钥。服务端为每个 EndpointId 分配唯一的 6 位机器编号，由 `A–Z` 和 `0–9` 组成，例如 `A7B2K9`。服务端持久保存并备份编号映射；同一 EndpointId 注册时返回原编号。

机器编号是查找入口，不是身份凭证。EndpointId 就是设备公钥，直接完整展示作为身份指纹，不再生成另一套指纹。私钥不上传给中央服务器。

## 主界面

主界面包含三个区域：

- **本机**：6 位机器编号、编号二维码、完整 EndpointId，分别支持复制。
- **远程访问设置**：“允许远程访问”开关、添加设备时使用的访问密码、已获准访问本机的设备管理入口。
- **已授权设备**：展示已经完成授权的远程设备，是日常操作的中心。

列表展示设备备注名、机器编号和状态。选中设备后提供“远程桌面”“文件共享”“查看 EndpointId”“断开连接”和“移除本地记录”等操作。支持多台设备同时连接，断开一台不影响其他设备。

普通操作不展示本地转发端口，不再展示 `10.x.x.1` 等虚拟地址。

## 添加新的设备

1. 点击“添加设备”，输入或扫描对方的 6 位机器编号，并输入对方设置的访问密码。
2. 客户端从中央服务获得对端身份信息。首次添加时，用户通过电话、当面等独立渠道核对对方应用中显示的完整 EndpointId。
3. 双方通过设备永久私钥签名证明身份，并建立经过身份验证的端到端加密连接。核对确认前，不向尚未信任的对端发送密码。
4. 访问密码仅在该加密连接中发送，由被控设备验证。中央服务器不接收密码，也不保存密码哈希。
5. 密码正确后，被控端仍弹出首次授权窗口，展示申请设备的机器编号和完整 EndpointId，供用户与对方核对。
6. 被控端明确点击同意后，在本机持久保存绑定申请方公钥的授权，并返回经过签名的授权结果。
7. 主控端验证并收到授权成功结果后，才把该设备加入“已授权设备”列表。

等待同意、被拒绝、密码错误、身份不一致、超时或设备离线时，不能将设备标记为已授权。中央服务器仅声称“已批准”也不能完成授权。

## 已授权设备的日常使用

添加成功后，用户选中设备即可打开远程桌面或文件共享，不需要每次重新输入 ArdUi 访问密码，也不需要对方每次点击同意。

此时由设备私钥证明身份，被控端检查本机保存的授权名单、允许访问开关和授权是否仍然有效。授权绑定永久公钥，不依赖 IP、显示名称或中央服务器的批准标志。

- 设备离线：保留列表记录，显示“离线”。
- 正在连接：显示连接进度，不提前显示为可访问。
- 授权已撤销：标记“需重新授权”，禁止继续访问。
- 编号对应的 EndpointId 发生变化：阻止连接，要求用户主动重新核对和添加，不能自动更新为服务器提供的新公钥。
- 重装后即使恢复了相同设备私钥，若本地授权名单未恢复，仍须重新授权；不能仅凭相同私钥推断旧授权已恢复。

ArdUi 访问密码是首次添加设备的授权口令。Windows 远程桌面和 SMB 的账户、密码及访问权限保持独立，ArdUi 授权不能代替 Windows 业务认证。

## 被控端的授权管理

被控端可查看“允许访问本机的设备”，展示备注、机器编号、完整 EndpointId 和连接状态，并支持单独撤销授权。

- 撤销某台设备：立即结束该设备的被控会话，后续必须重新申请。
- 关闭“允许远程访问”：停止新请求并断开被控会话；保留名单，但关闭期间任何设备都不能访问。
- 修改访问密码：撤销现有设备授权和待处理请求，断开被控会话；所有设备重新完成添加流程。
- 主控端“移除本地记录”：删除本机保存的列表与信任记录，不宣称已经远程撤销被控端保存的授权；被控端仍可独立撤销。

## 远程桌面与文件共享

### 远程桌面

点击“远程桌面”后，ArdUi 按需建立只监听本机回环地址的转发入口，经 ARD 连接被控端的 RDP 服务，并启动 Windows 远程桌面客户端。转发地址和端口由程序管理，用户不需要配置。

被控端需事先启用远程桌面，并具备支持远程桌面服务的 Windows 版本及账户权限。

### SMB 文件共享

点击“文件共享”后，程序通过 ARD 转发 SMB，完成共享连接并在 Windows 文件资源管理器中打开。首次访问可填写共享名及 Windows 账户，之后从设备列表打开对应共享；不承诺自动发现所有共享。

为在没有虚拟网卡的情况下保留 Windows 原生资源管理器入口，主控端的 SMB 功能以 **Windows 11 24H2、Windows Server 2025 或以上**为支持范围，使用系统 SMB 客户端的自定义目标端口能力。目标 SMB 服务仍可使用原来的 445 端口，由 ARD 进行转发。参见 [微软 SMB 自定义端口文档](https://learn.microsoft.com/en-us/windows-server/storage/file-server/smb-ports)。

本产品直接以 Windows 11 24H2 / Windows Server 2025 及以上为目标，不实现较旧 Windows 的兼容分支，不占用或替换系统 445 端口，也不自动关闭系统服务。多设备的转发入口、共享映射和凭据隔离须完成实际验证。

## 安全边界

首次身份核对必须使用独立渠道，核对的是双方客户端显示的完整永久 EndpointId。后续连接固定使用已核对的公钥。

临时会话公钥由永久设备私钥签名，签名绑定双方身份、当前请求、随机数和有效期。访问密码、业务凭据和流量授权密钥不交给中央服务器。

在客户端及私钥未被攻破、用户正确完成首次核对的前提下，中央服务器无法通过替换编号映射、临时会话公钥或伪造批准结果取得业务访问权限，也不能解密端到端业务内容。它仍可能阻断连接、返回错误状态或观察连接元数据。

## 技术与交付约束

- Windows 应用，Avalonia、.NET 8，纯 C# 构建界面，不使用 XAML。
- 客户端及安装入口的核心 C# 实现保持在一个文件中；类内成员不显式书写 `private`。
- `install.ps1` 是安装、修复与升级的唯一用户入口；客户端不要求用户运行 `--install`。核心 C# 客户端实现仍保持单文件。
- 使用自包含单文件发布。必要的 ARD 引擎和原生依赖内嵌在交付二进制中；如运行时需要子进程或原生文件，由程序校验并释放到受控缓存，不要求用户额外下载。
- “单二进制交付”不意味着系统上只能出现一个文件：安装后的配置、身份、授权记录和必要运行缓存独立存储，更新不得覆盖这些数据。
- 中央服务和 Relay 默认配置内置于二进制，安装时生成本地配置文件；配置中不包含私钥、访问密码或 Windows 业务密码。
- 不分发或调用 Wintun、tun2socks，不创建虚拟网卡，不提供虚拟 IP。
- 可信中央服务使用 `https://f.visnova.cn/`。
- NJ 的 ARD Relay 保持 8080，现有下载服务保持 8090；新版客户端通过 HTTPS 的 `/ardui` 路径分发。
- 不考虑旧版 ArdUi 的界面、协议或数据格式兼容，不保留旧 Wintun 方案。新版自身更新、重装恢复时的永久身份保持要求仍然有效。

## NJ 分发与一键安装

以下是计划发布的地址，当前 README 更新不表示新二进制或脚本已经上线：

| 地址 | 内容 |
| --- | --- |
| `https://f.visnova.cn/ardui/ArdUi.exe` | 由安装脚本自动获取的客户端二进制，不作为另一个用户安装步骤。 |
| `https://f.visnova.cn/ardui/install.ps1` | 一键下载、安装/修复并启动的 PowerShell 脚本。 |
| `https://f.visnova.cn/ardui/release.json` | 版本、文件大小、哈希及发布签名等元数据。 |

预期使用方式：

```powershell
irm https://f.visnova.cn/ardui/install.ps1 | iex
```

脚本职责：

1. 检查目标 Windows 版本和安装目录，默认使用当前用户的 `%LOCALAPPDATA%\ArdUi`。
2. 下载版本元数据及唯一的 `ArdUi.exe` 到临时路径，校验文件完整性和可用的发布签名，失败则停止。
3. 脚本负责创建或恢复永久身份，完成 TPM 记录及本地密钥文件的准备。可调用随客户端内置并经过验证的底层密码或 TPM 操作组件，但安装事务、失败处理和升级流程均由脚本控制；不得打印或上传私钥。
4. 检测已有安装时保留身份与授权数据；程序仍在运行时不强行覆盖，先提示正常退出后重试。更新采用校验后替换，保留可回退的旧文件。
5. 安装/修复成功后普通权限启动主界面，默认关闭被控功能。用户可在界面中设置访问密码并主动开启。
6. 同一命令重复执行应可重复运行，不能轮换身份、重置访问设置、清空授权名单，或在更新时自动开启被控功能。

脚本不安装虚拟网卡、不修改路由、不关闭系统安全策略，也不自行弹出提权窗口。TPM 操作若不满足平台权限要求，应明确报告安装前置条件，不能假装已经完成持久化。

### 安装渠道与服务器失陷的安全边界

`irm | iex` 首次执行的脚本本身来自 NJ，因此首次安装需要信任这一发布渠道。若 NJ 已被攻破，攻击者可直接替换脚本；从同一服务器下载的 SHA-256 清单无法独立防止这种攻击。

端到端身份核对保护的是已可信安装的客户端之间的通信，不能保护被替换成恶意软件的客户端。发布签名私钥应保存在 NJ 之外；已安装客户端的更新由本地固定发布公钥验证。若要让首次安装也抵抗 NJ 被攻破，必须通过独立可信渠道获得或验证启动器，不能仅依赖上述远程脚本命令。

## 验收要求

1. 安装创建一次身份；重装恢复相同 EndpointId，并取得原机器编号；日常启动不调用 TPM。
2. 密码正确但被控端尚未同意时，不能加入已授权列表或访问任何业务服务。
3. 双方首次 EndpointId 核对完成且被控端同意后，才能持久保存授权。
4. 后续凭设备身份和被控端授权名单直接访问；无需重复输入 ArdUi 访问密码。
5. 服务器替换永久公钥、临时公钥或批准结果时，客户端拒绝连接。
6. 单设备撤销、全局关闭和修改密码的行为与本文一致。
7. 多设备并发、离线重连和单设备断开互不干扰。
8. 实际验证 Windows RDP 登录、SMB 共享打开及多设备凭据隔离；传输回环测试不能代替这些验收。
9. 整个访问流程不安装或调用 Wintun，不修改系统路由，不自动提权。

10. 对外只交付一条 `irm .../ardui/install.ps1 | iex` 安装命令；脚本自动获取唯一客户端 EXE，无需另装 .NET、ARD、Wintun 或其他客户端依赖。
11. 从 `/ardui/install.ps1` 完成下载、校验、安装和启动；重复执行不改变身份或已有授权，更新不自动开启被控功能。
12. 关闭被控功能后不接受新连接、结束已有被控会话，但已授权远程设备的主动访问仍可使用。
